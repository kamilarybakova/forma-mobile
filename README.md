# Planiz — приложение дизайнера

Самостоятельный Flutter-проект рядом с `forma/` и `backend/`. iOS, Android, Web и macOS. Приложение использует публичный `/api/v1/` существующего FastAPI-сервера; сайт и приложение работают с одной студией и одними данными. WebView для кабинета не используется.

## Запуск

Проверено с Flutter 3.44.6 / Dart 3.12.2. Минимальная iOS — 14.0. Сначала запустите существующий backend по инструкции `../backend/README.md`.

```sh
cd forma_mobile
flutter pub get
flutter run -d macos \
  --dart-define=API_BASE_URL=http://127.0.0.1:8001/api/v1/ \
  --dart-define=SITE_BASE_URL=http://127.0.0.1:5173
```

Для iOS выберите устройство из `flutter devices` и передайте его ID через `-d`. Для Android-эмулятора используйте `http://10.0.2.2:8001/api/v1/`; для физического телефона — доступный ему адрес API. Для Web задайте фиксированный порт (`--web-port=5174`) и добавьте его origin в `CORS_ALLOWED_ORIGINS` backend. При обращении по локальной сети добавьте адрес сервера в `ALLOWED_HOSTS`.

Для рабочего сервера передайте реальные HTTPS-адреса через те же `--dart-define`. URL по умолчанию относятся только к локальной разработке. В приложении нет `INTERNAL_API_KEY`, паролей БД или служебных серверных ключей. App Store/Google Play подпись и публикация в эту задачу не входят; свой Apple Team следует настроить в Xcode для устройства.

## Архитектура

```text
lib/
  app/                    # composition root, DI, приложение, адаптивная оболочка
  core/
    network/              # Dio, ошибки, сериализованное обновление сессии
    storage/              # абстракция TokenStore + защищённое хранилище
    files/                # выбор/загрузка/скачивание, native/web реализации
    theme/                # цвета, типографика, общие стили
    widgets/              # общие элементы и формы
  features/
    auth/
    workspace/
    portfolio/
    studio/
    billing/
    specifications/
      data/               # реализации репозиториев, адаптация API
      domain/             # контракты, модели и правила предметной области
      presentation/       # экраны, состояние и пользовательские действия
```

`get_it` используется в composition root: репозитории и FileService передаются в экраны, контроллеры получают репозитории через конструкторы. Domain не импортирует Flutter, Dio и get_it. Контроллеры — ChangeNotifier; общая обработка загрузки/ошибок в AsyncController. Подписка не влияет на видимость кабинета. Таблицы спецификаций используют серверную версию, анкеты — optimistic locking; 409 не скрывается. ТЗ и редактор портфолио предупреждают при выходе с несохранёнными изменениями. Посещённые вкладки сохраняют состояние и прокрутку.

Сессия хранится одной записью в flutter_secure_storage. Для iOS подключён Keychain entitlement; macOS использует приватный legacy Keychain без sharing/provisioning. Параллельные 401 используют одну операцию refresh и новую пару токенов. Временный сбой refresh не стирает сессию. Автоматическое повторение произвольных запросов при сетевой ошибке не выполняется.

## Оформление

Визуальный язык — «чертёж»: тёплая бумага, глубокий синий и чернильный цвет сайта. Шрифт интерфейса — Manrope (OFL, `assets/fonts/LICENSE_MANROPE`), логотип сохраняет начертание сайта (Liberation Sans Bold). Статические начертания 400–800 получены из вариативного файла Google Fonts. Цвета и стили текста заданы в `core/theme/app_theme.dart`, общие элементы — в `core/widgets/ui.dart`, графика — в `core/widgets/plan_art.dart`. Планировка на карточке проекта строится из его ID и служит только для узнавания: это декоративный рисунок, а не реальная геометрия объекта.

## Реализованные сценарии

- Вход, регистрация, восстановление пароля по email, выход и восстановление сессии.
- Обзор практики, поиск и фильтры проектов, создание объекта.
- Все разделы ТЗ, черновик/готовое ТЗ, приглашение клиента, отзыв и обновление ссылок.
- Замеры и перезамеры с неизменяемой историей; этапы планировок, концепций, визуализаций и рабочей документации.
- Загрузка файлов и скачивание через авторизованный API; круги правок, чтение комментариев, примечания к файлам, комнаты визуализаций, отправка комплекта на согласование и новый вариант.
- Добавление рабочих чертежей, загрузка, завершение/пропуск документации; подбор материалов; перенос утверждённого проекта в портфолио.
- Спецификации: создание, переименование, категории, позиции, фотографии, удаление, PDF актуальной версии.
- Портфолио: создание/редактирование/удаление проекта, видимость, порядок, фотографии и подписи, планировки и концепции.
- Профиль студии, услуги/цены, этапы, отзывы, социальные сети, контакты и имя пользователя.
- Шаблоны, палитры, состояние сайта, тарифы, серверный расчёт цены, согласие на публикацию, пробный месяц, история и отмена ожидающей заявки.

Согласование клиентом выполняется по существующей веб-ссылке. Демо шаблонов, превью сайта, письмо восстановления пароля и ручная оплата через WhatsApp открывают существующие веб-сценарии. Для приватного превью браузеру может потребоваться отдельный вход; bearer-токены туда не передаются. Платежи не имитируются: цена и переходы подписки рассчитываются сервером.

## Изменения общего продукта

В `backend/app/routes.py` кабинет и клиентский портал отвязаны от `active_order/includes_workspace`. Владение студией, срок/отзыв ссылки, версии и квоты сохранены. Без активной подписки остаётся существующая квота 10 ГБ. Публикация портфолио по-прежнему требует действующей подписки.

На сайте кабинет теперь доступен до подключения сайта, на базовом тарифе и после окончания подписки. Для этого изменены два компонента панели в `forma/components/account/`. Изменения сервера и сайта нужно выложить вместе с приложением; миграция БД не требуется. Названия и цены существующих тарифов не менялись; поле каталога `includes_workspace` сохранено для совместимости, но больше не является разрешением доступа к кабинету.

## Проверки

```sh
flutter analyze
flutter test
flutter build web --release
flutter build apk --debug
flutter build ios --simulator
```

После изменения минимальной iOS для SwiftPM выполните `flutter build ios --config-only --no-codesign`.

В `test/` — проверки конкурентного refresh, отказов сессии, входа и адаптивности всех вкладок и этапов на 320×568, 390×844, 768×1024, 1024×768, 1440×1000, а также текста ×1,5. Снимки главного экрана в `test/goldens/`; обновление — `flutter test --update-goldens`. Тестовые записи существуют только в тестовом адаптере, в рабочем приложении нет демонстрационных аккаунтов/проектов.

Результаты сборок, фактические проверки и ограничения — в [VALIDATION.md](VALIDATION.md).
